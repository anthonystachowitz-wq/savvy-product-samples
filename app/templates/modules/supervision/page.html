Supervision in the loop

Pre-approval review for adviser marketing at a 12-household practice. The model drafts from an approved fact sheet and classifies every claim. Marta Ellsworth, chief compliance officer, approves or rejects with an evidence file. Nothing is sent, scheduled, or filed.

How this is built

Prompt pattern, eval, and what failed

Method page

Prompt pattern

  1. One generation call per brief. Inputs are the brief and the approved fact sheet. Output is strict JSON: headline, body, disclosure ids.
  2. One classification call per draft. The model splits the body into claims, types each one, and cites a fact or disclosure id.
  3. A deterministic source check verifies every percentage and currency figure against the cited fact. A supported label the source does not carry is downgraded before the gate.
  4. The policy gate is code. Any fail blocks the approval POST, the same checks that disabled the form.
  5. One revision call for the blocked draft, then a fresh classification call on the revision before it can be approved.

The eval

Twelve hand-labelled claims, one recorded classification call, scored on the classifier the page uses. {% if eval %}{{ eval.exact }} of {{ eval.cases }} exact, precision {{ eval.precision }}, recall {{ eval.recall }}.{% endif %} The cases and labels are in data/modules/supervision/eval_cases.json; the script that writes the score is scripts/eval_supervision.py.

What failed

  • Performance claims read as fact. In the eval list, "The S&P 500 total return was 12.4% in 2025" came back factual and supported, so the performance flag missed. The identical sentence came back performance inside the drafts, so the label is context sensitive.
  • Right flag, wrong type. "The practice has grown 38% since 2023" was typed performance rather than a factual claim with no source. The flag fired, the type did not match the label.
  • The first classification pass over-flagged process language as unsupported: "please reply to this email", "we do not give tax advice". All four drafts blocked. The prompt now extracts only checkable claims and the support rule accepts disclosure ids.
  • Generation undershot every brief. Drafts ran 44 to 111 words against briefs asking 60 to 190. The word count sits next to the limit on every draft.
  • The adviser's supplied line was reproduced word for word, as instructed. That is the blocked example, and the gate refused it three ways: performance type, unsupported claim, and a number outside the fact sheet.

Guardrails

  • No approval without a named, independent approver. Self-review is refused on the server.
  • No approval while a policy check fails, and no approval from a form post that skips the checks.
  • Every attached disclosure comes from the fact sheet by id. The model does not type disclosure text.
  • An approval writes an evidence file with the artifact hash and a five-year retention date, and one audit event.
  • Client-facing work for a household without recorded consent cannot be approved for that audience.

Not in this build

  • No send, no scheduling, no CRM, no custodian connection. A sealed evidence file is the end of the workflow.
  • No legal opinion. The policy rules and the fact sheet are synthetic.
  • No reviewer telemetry, so the cycle-time model stays an assumption set.
